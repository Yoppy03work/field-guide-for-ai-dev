## やりたかったこと

このサイトの PR ごとに、人間レビュー前に「型 / lint / build」のチェックを
自動で回し、ミスを早期に拾いたかった。Codex の自動レビューも併用したい。

## 使った AI / ツール

- GitHub Actions（lint / typecheck / build の CI、`docs/14_github-templates.md` から `.github/workflows/ci.yml`）
- Codex（PR コメントベースのレビュー、AGENTS.md の観点で実施想定）

## 実際に投げた指示

PR テンプレ（`.github/PULL_REQUEST_TEMPLATE.md`）に以下の観点リストを置き、
Codex に「ここ見て」と明示している。

```
- TypeScript strict 違反が無いか
- Tailwind v4 の @apply が混入していないか
- インラインスタイルが混入していないか
- <Glossary> を使うべき用語が生テキストになっていないか
- <StatusBadge> がページ先頭に置かれているか
- アクセシビリティ要件（alt / aria-* / フォーカス可視化）を満たすか
```

## 返ってきた結果

- 最初の CI（PR #2）は **`pnpm-workspace.yaml` の `packages` field 不在**で fail
  → CI の pnpm を v9 → v10 に揃え、workspace に `packages: ["."]` 追加で復旧
- それ以降の PR では typecheck / lint / build が安定して green
- PR #9 では `<a>` タグでの内部 nav に対する `@next/next/no-html-link-for-pages` を
  lint が拾い、`next/link` への置き換え修正を 1 件取り込んだ

## 良かった点

- 「`@apply` 入っちゃった」「any 混入」みたいな機械的事故は CI / lint が一発で拾う
- pnpm workspace の落とし穴（`packages` 必須）も build ログから即特定できた

## 微妙だった点

- 設計判断（このディレクトリ構造でいいか、コンポーネント分割の粒度）は
  CI / lint の守備範囲外
- CI pnpm のバージョン違いでの初回失敗は、ローカルでは見えない事故

## 駆け出しへのアドバイス

PR テンプレに「Codex への指示」「Antigravity への指示」セクションを最初に
入れておくと、AI レビューの的が絞られる。指示の解像度が上がるほど、
レビューの精度も上がる。
