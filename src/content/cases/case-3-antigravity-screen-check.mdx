## やりたかったこと

別の Web アプリ（先週授業で触ったもの）のプレビュー URL に対し、
画面崩れがないかをブラウザ AI で巡回確認したかった。

**仮説**: 自分でモバイル幅を切り替えて巡回するより、AI に任せた方が
観点漏れが減る。

## 使った AI / ツール

- **Antigravity**（ブラウザ操作 AI）
- **Vercel Preview**（チェック対象の URL 発行元）

## 実際に投げた指示

```text
このプレビュー URL を 30 秒見て、以下を報告してください。

URL: <該当の Preview URL>
ビューポート: 375x812（モバイル幅）

観点:
1. レイアウト崩れ（横スクロール、要素の重なり）
2. ファーストビューで意図した文言が見えているか
3. ボタンが画面内に収まっているか

スクショは /tmp に保存してください。
報告は「致命 / 軽微」を分けて、それぞれ 1 行で。
```

<Callout type="tip" title="観点を 3 つに絞る">
  最初は観点を欲張らず 3 つに絞ると、報告が散漫にならない。
  「致命 / 軽微」の二段で要約させると、優先度の判断がしやすい。
</Callout>

## 返ってきた結果

- スクショ複数枚（ホーム / 1 つ目のセクション / フッタ）
- 「ここで横スクロールが出る」「このボタンが画面外」など気づきのリスト
- 人間が気づきにくい **モバイル幅でのテキスト改行崩れ**を 1 件発見
- 「致命」: 1 件（モバイル幅でのレイアウト崩れ）
- 「軽微」: 2 件（フッタの色コントラスト / リンクの下線がない）

## 良かった点

- 人間の目では見落としやすいレイアウト崩れを拾える
- スクショと一緒に「位置と理由」を返してくれる
- 「致命 / 軽微」フォーマットで返ってきたので、修正の優先度が即決できた
- 自分でブラウザを開いて DevTools のレスポンシブモードを切り替えるより速い

## 微妙だった点

- **1 回しか使っていないので、安定して効くかは未検証**
- 「30 秒見て」のような時間指定や、保存先指示の精度がレビュー品質に直結
- 2 回目以降の同じ URL に対する挙動はわからない（毎回少し違う観点で見る？）
- 報告内容に「主観」が混じることがある（「この色は微妙です」）→ 観点を客観化させる必要

## Lessons Learned

1. **観点 3 つに絞る**: 多いと「特に問題なし」で終わる
2. **「致命 / 軽微」フォーマットを強制**: 主観を客観に近づける
3. **スクショ保存先を明示**: `/tmp` のような場所を必ず指定
4. **ビューポートを明示**: 375x812（iPhone 系モバイル幅）が崩れやすい
5. **1 回限りで判断しない**: 複数回試して「自分の道具」になる
6. **役割分担**: Antigravity は機械的巡回。デザイン判断は人間
