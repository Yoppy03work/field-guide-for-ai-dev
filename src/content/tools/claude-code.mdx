## ひとことで言うと

**ターミナルで対話しながらコードを書ける AI**。
リポジトリの中で動き、ファイルの読み書き / コマンド実行 / Git 操作までセットでこなす。

## まずやること

```bash
# Claude Code を起動して、リポジトリの構造を聞く
claude
> このプロジェクトを 5 行で説明して

# 次に小さい依頼で粒度をつかむ
> README に1行追加して
```

これで「自分の repo を理解させる → 小さい変更を頼む」の感覚がつかめます。

## CLAUDE.md の書き方（Claude Code に効くコツ）

プロジェクトルートに `CLAUDE.md` を置くと、Claude Code はそれをコンテキストとして読みます。

**必ず書きたいこと**：

- このプロジェクトは何か（1〜3 行）
- 技術スタックと「触らない方針」
- 専門用語のルール（「ひとことで言うと」付与など）
- 危険操作のルール（削除・破壊的変更の前は確認）

このリポジトリの [CLAUDE.md](https://github.com/Yoppy03work/field-guide-for-ai-dev/blob/main/CLAUDE.md) もそのまま参考にできます。

<Callout type="tip" title="CLAUDE.md の質 = 出力の質">
  カラーコード、禁止事項、必須コンポーネントを書いておくと、最初の 1 振りで仕様に乗ります。逆に CLAUDE.md が薄いと、何度も振り直すことに。
</Callout>

## 効果があったこと

- CLAUDE.md を整備すると数時間分の作業を任せられる
- ファイル横断のリファクタや、新規ページの雛形作成が速い
- Codex の指摘を取り込む修正サイクルが半自動になる
- ドキュメントとコードを並行して整える pull がきく

## よくある失敗

- 大きい変更は粒度を分けないとブレる（1 PR で全部やらせると迷走）
- 破壊的操作（rm / git reset）の前に確認を求める運用を徹底しないと事故る
- 「いい感じに作って」だけの指示は AI が広く解釈して、想定外のファイルに触れる
- CLAUDE.md がない / 薄い repo では、毎回プロンプトで方針を補う羽目に
- AI 出力をそのまま commit する → 必ず差分を読んで判断する

## 駆け出しが最初に試すなら

- 自分のリポジトリで `claude` を起動して「このプロジェクトを説明して」と聞いてみる
- 次に「README を1行追加して」など小さい依頼で粒度感をつかむ
- 慣れたら CLAUDE.md にカラーパレット / 禁止事項を書いて再依頼
