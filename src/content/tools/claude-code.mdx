## このツールをひとことで言うと

**ターミナルで対話しながらコードを書ける AI**。
リポジトリの中で動き、ファイルの読み書き / コマンド実行 / Git 操作までセットでこなす。

## 開発フローのどこで使うか

- [Step 3: Claude Code に実装を依頼する](/workflow#step-3)（実装担当）
- 補助的に Step 1（Issue 草案）、Step 4（PR description）、Step 8（Cases 執筆）にも使える

## CLAUDE.md の書き方（このページ独自）

プロジェクトルートに `CLAUDE.md` を置くと、Claude Code はそれをコンテキストとして読みます。
**必ず書きたいこと**：

- このプロジェクトは何か（1〜3 行）
- 技術スタックと「触らない方針」
- 専門用語のルール（「ひとことで言うと」付与など）
- 危険操作のルール（削除・破壊的変更の前は確認）

このリポジトリの [CLAUDE.md](https://github.com/Yoppy03work/field-guide-for-ai-dev/blob/main/CLAUDE.md) も
そのまま参考にできます。

## 実際に試したこと

- このサイトの実装全工程（Next.js 16 init / コンポーネント / MDX / ページ実装）
- 過去リポジトリの調査・読解（「このコードは何をしてる？」を聞く使い方）

## 効果があったこと

- CLAUDE.md を整備すると数時間分の作業を任せられる
- ファイル横断のリファクタや、新規ページの雛形作成が速い

## 微妙だったこと

- 大きい変更は粒度を分けないとブレる（1 PR で全部やらせると迷走）
- 破壊的操作（rm / git reset）の前に確認を求める運用を徹底しないと事故る

## 駆け出しが最初に試すなら

- 自分のリポジトリで `claude` を起動して「このプロジェクトを説明して」と聞いてみる
- 次に「README を1行追加して」など小さい依頼で粒度感をつかむ
