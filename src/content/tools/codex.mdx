## ひとことで言うと

**PR 提出時に自動でレビューコメントを書いてくれる AI**。
型エラー / 命名 / テスト漏れなどのチェックを、人間レビュー前にこなす。

## まずやること

1. repo に [Codex を連携](https://chatgpt.com/codex/cloud/settings/general)
2. PR テンプレに「Codex への指示」欄を入れる
3. PR を 1 つ出して、Codex のコメントを観察する

```markdown
## Codex への指示

このPRをレビューしてほしい観点:

- [ ] TypeScript strict 違反が無いか
- [ ] @apply / インラインスタイル混入が無いか
- [ ] アクセシビリティ要件（alt / aria-* / focus）を満たすか
```

## 開発フローのどこで使うか

- [Step 5: Codex にレビューしてもらう](/workflow#step-5)
- PR テンプレに「Codex への指示」欄を用意すると、的を絞ったレビューが来る

## 実際に試したこと

- このサイトの 22+ PR で Codex の自動レビューを実運用
- PR #9 で **P1 critical**（`Object.hasOwn` 必須）を 1 件発見、PR #16 で対応
- PR #18 で **P2 yellow** ×4 を同 PR 内で対応（clipboard 失敗 / regex / docstring / touch UI）
- AGENTS.md にレビュー観点を P1/P2/P3 で細分化して指示

## 効果があったこと

- 人間レビュー前のフィルタとして優秀（型 / lint / 命名）
- `Object.hasOwn` のような「気付きにくいセキュリティ系」を拾ってくれた
- 「@apply 入っちゃった」「any 混入」のような機械的事故は一発で潰せる
- 重要度（P1/P2/P3）ラベルで対応の優先度がぶれない

## よくある失敗

- 的外れ指摘もある（10〜20%）→ 全部対応しなくていい、判断は人間
- 設計レビュー（このアーキでいいか）は Codex の守備範囲外
- content-heavy な PR では応答しない / 遅いことがある（このサイトでも Phase 3 以降観測）
- 「Approve だけして本文を読まない」と AI 任せの危険状態に
- AI の指摘の深刻度を見極めずに全部潰そうとして、merge が遅れる

## 駆け出しが最初に試すなら

1. 自分のリポジトリで PR を 1 つ出す（小さい変更で OK）
2. Codex のコメントが来るのを 5〜10 分待つ
3. 1 件だけ取り込んでみる（全部対応しなくていい）

<Callout type="tip" title="Codex 対応の運用">
  PR description に「Codex 対応欄」を入れて、指摘ごとに「対応済み / 対応しない理由 / Issue 化」を明記すると、後から見返したときに教材になります。
</Callout>
