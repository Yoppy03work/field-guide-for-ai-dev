## このチュートリアルでやること

自分の Vercel Preview URL（または本番 URL）に対して、
Antigravity（ブラウザ操作 AI）を使って画面崩れを巡回確認させます。
最後に、報告された崩れを 1 件 PR で直してから再確認させる「やり取りの型」までやります。

## 前提

- Vercel で deploy された自分の Web アプリの URL がある
- Antigravity を起動できる環境がある（セットアップは公式に従う）
- ブラウザで人間が手動チェックできる程度の画面（複雑な認証ゲートは外しておく）

## 全体像

```text
1. 確認したい URL とビューポートを決める
2. 指示の型を準備する
3. Antigravity に投げる
4. 報告された崩れを 1 件 PR で直す
5. 同じ指示で再確認させる
```

## ステップ 1: 確認したい URL を決める（3 分）

**やること**

- 対象の URL を 1 つに絞る（最初は `/` ホームページが楽）
- どの画面サイズで見せるか決める（モバイル幅 375x812 がハマりどころが多い）
- 「何を見て欲しいか」を 3 つに絞る（多すぎると報告がぼやける）

**期待される結果**

- URL / ビューポート / 観点 3 つが手元にメモできた状態

<Callout type="tip" title="観点 3 つの例">
  - レイアウト崩れ（横スクロール、要素の重なり）
  - ファーストビューで意図した文言が見えているか
  - フォーカスを Tab で送ったときに skip-link が見えるか
</Callout>

## ステップ 2: 指示の型を準備する（5 分）

**やること**

以下の 4 要素を含めた指示文を用意します。

```text
このプレビュー URL を 30 秒見て、以下を報告してください。

URL: <あなたの Preview URL>
ビューポート: 375x812（モバイル幅）

観点:
1. レイアウト崩れ（横スクロール、要素の重なり）
2. ファーストビューで意図した文言が見えているか
3. フォーカスを Tab で送ったときの可視化

スクショは /tmp/preview-check に保存してください。
報告は「致命 / 軽微」を分けて、それぞれ 1 行で。
```

**期待される結果**

- コピペで使える指示テンプレが手元にある

**うまくいかない時**

- 指示が抽象的だと「特に問題なし」で終わりがち → 観点を 3 つに絞り具体化する
- 観点が多すぎると報告が散漫 → 「致命 / 軽微」の二段で要約させる

<Callout type="tip" title="型を保存しておく">
  この指示は何度も使い回します。`docs/antigravity-prompt.md` のような
  ファイルに保存しておくと、PR ごとに再現できます。
</Callout>

## ステップ 3: Antigravity に投げる（3 分）

**やること**

1. Antigravity を起動
2. 指示テンプレを貼る
3. 30〜60 秒待機

**期待される結果**

- スクショ複数枚 + 「ここが崩れている」「ここは OK」のリスト形式の報告
- 「致命」と「軽微」が分かれている

**うまくいかない時**

- スクショ保存先が出力されない → 指示で保存先パスを明示
- 「30 秒見て」が短すぎ／長すぎ → 自分のページ規模に合わせて調整
- 観点に答えてもらえない → 観点を箇条書きにし、それぞれ「Y/N + 一言」で答えさせる形式に

## ステップ 4: 報告内容を 1 件取り込む（5 分）

**やること**

1. 報告された崩れの中で 1 件選ぶ（致命を優先）
2. ローカルで再現確認 → 修正
3. ブランチを切って commit
4. PR を作って Vercel Preview を待つ

**期待される結果**

- 同じ Preview URL で、修正後の状態が見える

**うまくいかない時**

- ローカルで再現しない → DevTools のレスポンシブモードで Antigravity と同じビューポートに合わせる
- 修正が他箇所を壊す → CSS の利き方を確認、Tailwind v4 のクラスは「親で適用」を意識

## ステップ 5: 同じ指示で再確認させる（4 分）

**やること**

1. 修正後の Preview URL に対して、ステップ 2 と同じ指示を貼る
2. URL だけ新しいものに差し替える
3. 同じ観点で報告を受ける

**期待される結果**

- 直した箇所が「OK」と報告される
- 別の崩れが新しく見つかることもある（その場合はステップ 4 に戻ってループ）

<Callout type="tip" title="人間と AI の役割分担">
  Antigravity は「機械的な巡回」が得意。デザインの良し悪しや UX の判断は
  人間がやる。役割を混ぜないと「この色は微妙です」のような主観的な
  指摘が増えて、ノイズになります。
</Callout>

## できたか確認

- [ ] 指示テンプレを書いて Antigravity に投げられた
- [ ] スクショ + 「致命 / 軽微」分かれたリスト形式の報告を受け取れた
- [ ] 報告内容を 1 件、自分の repo に修正として取り込めた
- [ ] 修正後に同じ指示で再確認させられた
- [ ] 1 回限りでなく、PR ごとに回す運用イメージを持てた
- [ ] うまくいかなかった場所を 1 つ説明できる

## ハマりどころまとめ

- 指示が抽象的 → 観点を 3 つ以内に絞り、`致命/軽微` で要約
- 環境差で再現できない → DevTools のレスポンシブモードでビューポートを合わせる
- 報告が主観に寄りがち → 「観点 3 つに対して Y/N + 一言」のフォーマットを強制
- スクショが分散して見にくい → 保存先を 1 ディレクトリに固定
- バージョン差異 → Antigravity のバージョンと URL を PR description に記録

## なぜこれを学ぶ価値があるか

- 「人間が見落としやすいレイアウト崩れを拾える」場面で効く
- Vercel Preview URL とセットで使うと、レビュー体験がぐっと変わる
- ただし、**1 回限りの体験で過剰一般化しない**ことが重要（このページの 🟡 はそういう意味）
