## 各ページ仕様

### 1. `/` ホーム

#### 目的
- 30 秒で「このサイトが何で、どこから読めばいいか」を伝える
- **「まずはここから」** で `/learn/github` へ自然に誘導
- ワークフロー全体像を見せて `/workflow` への導線を確保

#### セクション構成（縦に並ぶ）

1. **ヒーロー**
   - タイトル / サブタイトル
   - CTA：「まずはここから」（→ `/learn/github`）
   - 背景は控えめ

2. **このサイトについて（3 行）**
   - 大学1年生〜駆け出し向け、AI 開発フローの教材アプリ
   - 主役は AI ツールではなく「フロー」
   - 🟢🟡🔵 で情報源を明示

3. **まずはここから ブロック**
   - `/learn/github` への大きな誘導カード
   - 「GitHub の Issue / Branch / PR / Merge を、ひとことで言うと付きで解説」

4. **AI 開発フロー要約**
   - 8 ステップの省略図
   - 「詳細は `/workflow` へ」

5. **ツール早見グリッド（7 つ）**
   - 2x4 または 3x3 のカード、それぞれにバッジ表示

6. **最新 Cases 3 本**
   - カード形式（タイトル / 日付 / バッジ / 抜粋）

7. **About への誘導**

### 2. `/learn/github` GitHub 入門（最重要の入口）

#### 目的
- 大学1年生でも読める GitHub の用語解説
- 各セクションに「ひとことで言うと」「具体例」を必ず置く
- 最後にミニ課題を 1 つ通す

#### セクション順序（9 トピック）

| # | セクション | ひとことで言うと |
|---|---|---|
| 1 | GitHub って何？ | チームでコードを共有・保存する場所 |
| 2 | リポジトリとは？ | プロジェクトを置く場所 |
| 3 | Issue とは？ | やることメモ |
| 4 | Branch とは？ | 作業用の分岐 |
| 5 | Pull Request とは？ | 変更を見てもらう提出箱 |
| 6 | Review とは？ | 変更内容の確認 |
| 7 | Merge とは？ | 本番の流れに合流させること |
| 8 | Vercel Preview で確認するとは？ | 公開前にお試し画面で見ること |
| 9 | AI 開発ではどこで Claude Code / Codex / Antigravity を使う？ | フローの各ステップで AI を差し込む |

#### 各セクションの構造

```
┌─ セクション ────────────────────────────────────┐
│ # ◯ Issue とは？                                │
│                                                 │
│ ひとことで言うと:                                 │
│ 「やることメモ」                                  │
│                                                 │
│ 具体例:                                          │
│ 「トップページに自己紹介カードを追加する」         │
│  みたいなタスクをここに書きます。                  │
│                                                 │
│ 何のためにあるのか:                               │
│ ・チームで「誰が何をやるか」を見える化する         │
│ ・後から「なぜこの変更をしたか」が追える           │
│                                                 │
│ 試してみよう:                                     │
│ 自分のリポジトリで Issue を1つ立ててみる          │
└─────────────────────────────────────────────────┘
```

#### 最後のミニ課題

```
お題: 「トップページに自己紹介カードを追加する」を最後まで通す

1. Issue を立てる
2. Branch を切る (feature/profile-card)
3. Claude Code に実装を依頼する
4. PR を作る
5. Codex にレビューしてもらう
6. Antigravity で画面を見てもらう
7. Vercel Preview で確認する
8. Merge する
```

→ この課題は `/workflow` の8ステップと完全に対応。

### 3. `/workflow` 中心ページ

#### 目的
- 開発フロー全体と AI の差し込みポイントを 1 ページで見せる

#### セクション構成

1. **このページで学べること**（3 行）
2. **全体フロー Mermaid 図**
3. **8 ステップ詳解**
   - Issue を立てる
   - Branch を切る
   - Claude Code に実装を依頼する
   - PR を作る
   - Codex にレビューしてもらう
   - Antigravity で画面確認する
   - Vercel Preview で確認する
   - Merge して公開する

#### 各ステップの構造

```
┌─ ステップ N ────────────────────────────────────┐

│ ◇ なぜ必要なのか                                  │
│ ◇ 初心者がハマりやすいところ                       │

│ ◇ 自分で試すための小さな課題                       │
│                                                 │
│ 関連:                                            │
│ ・/learn/github のセクションX                     │
│ ・/tools/[該当ツール]                             │
│ ・/cases/[該当Case]                               │
└─────────────────────────────────────────────────┘
```

### 4. `/tools` ツール一覧

- 7 つのカードを 2x4 / 3x3 グリッドで配置

### 5. `/tools/[slug]` 各ツール詳細

#### 共通テンプレ（必ずこの順）

1. **ヒーロー**

   - ステータスバッジ（🟢/🟡/🔵）

4. **実際に試したこと**

5. **効果があったこと**

6. **微妙だったこと**

7. **駆け出しが最初に試すなら**（5 分で試せる課題）

8. **関連する Case / Issue / PR**

### 8. `/about`

- 著者：yoppy（プロフィールは控えめに）

- ライセンス：コードは MIT、コンテンツは CC BY 4.0
- お問い合わせ：GitHub Issues

## URL 命名規則

- 全て小文字
- 単語区切りは `-` ハイフン
- 日本語 URL は使わない
- Case の slug：`case-N-キーワード`（例：`case-1-claude-code-ui`）

## メタ情報（全ページ）

- `<title>`: ページタイトル | AI Dev Field Guide
- `<meta description>`: 100〜160 文字、各ページで重複しない
- OG 画像：MVP では **共通画像 1 枚**（記事別生成は Phase 2）
- canonical URL：HTTPS の正規 URL

## レスポンシブ・ブレークポイント

| デバイス | 幅 | レイアウト方針 |
|---|---|---|
| モバイル | 〜767px | 1 カラム、タップしやすい余白 |
| タブレット | 768〜1279px | 2 カラム |
| デスクトップ | 1280px〜 | 最大幅 1200px、中央寄せ |

## アクセシビリティ要件（重要）

- 🟢🟡🔵 のバッジは絵文字 + テキストラベルを必ず併記
- フォーカス可視化を維持
- 見出し階層を守る
- すべての画像に alt
- カラーコントラストは WCAG AA

## 用語の表示ルール（v2 で追加）

- 専門用語は初出時に **「ひとことで言うと」** を必ず併記
- 用語ハイライト（薄い下線）を入れて目立たせる
- 用語をクリックすると `/learn/github` の該当セクションへスクロール（任意機能、Phase 2）
