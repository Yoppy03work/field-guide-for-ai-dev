## あなた（レビュアー）への依頼

著者は **AI Dev Field Guide** という Web サイトをこれから 1〜2 週間で実装します。
**`09_claude-brief.md` の方針** に従って、仕様書・計画書を v2 として書き直しました。

実装着手前に、この仕様の **抜け漏れ・矛盾・実現性の問題** を指摘してください。

### 依頼の優先順位

1. **致命的問題**（このまま実装すると失敗する）
2. **改善提案**（より良くなる代替案）
3. **誤字脱字・体裁**（最後でよい）

### 依頼に含めないでよいもの

- AI API を使う提案（**今回は使わない方針が固定**）
- ツール紹介を主役にする提案（**主役は AI 開発フローで固定**）
- 多言語対応の提案（**日本語のみで固定**）
- バックエンド機能の提案（**静的サイトで固定**）
- ブログ機能の追加提案（**Cases に統合済みで固定**）
- Pagefind / RSS / ダーク / 記事別 OG 画像 / 高度アニメ（**Phase 2 へ後送り済**）

## レビュー観点チェックリスト（v2）

### A. 方針整合（`09_claude-brief.md` との一致確認）

- [ ] 主役が「AI 開発フロー」になっているか（ツール紹介が主役になっていないか）
- [ ] 対象読者が「大学1年生〜駆け出し」に拡張されているか
- [ ] `/learn/github` が入口として設計されているか
- [ ] `/workflow` が中心ページになっているか
- [ ] `/cases` が制作ログとして設計されているか
- [ ] ツールが7本（GitHub を含む）になっているか
- [ ] MVP が6ページに絞り込まれているか

### B. 仕様（`01_spec.md`）

- [ ] ターゲット読者の解像度は十分か
- [ ] 提供価値の差別化（特に「AI ツールの使い方ではなくフローを教える」点）が明確か
- [ ] In Scope / Out of Scope の線引きは適切か
- [ ] 機能要件 F1〜F8 に欠けがないか
- [ ] 非機能要件は妥当か
- [ ] ツール7本の選定と役割分担は適切か
- [ ] Cases 4 本のテーマで「読みごたえ」が出るか

### C. 計画（`02_plan.md`）

- [ ] 14 Day スケジュールは現実的か
- [ ] `/learn/github` に Day 3-4 の2日間を割く判断は妥当か
- [ ] `/workflow` を Day 5 で1日で書く判断は妥当か
- [ ] Cases 執筆を Week 2 に集中させる判断は妥当か
- [ ] マイルストーン M1〜M7 は妥当か
- [ ] リスクと対策は十分か
- [ ] AI ツールの役割分担は適切か

### D. ページ構成（`03_pages.md`）

- [ ] サイトマップに必要なページは揃っているか
- [ ] 各ページの目的は明確か
- [ ] `/learn/github` の9セクション順序は学習導線として妥当か
- [ ] `/workflow` の8ステップ詳細テンプレで「真似できる」レベルになるか
- [ ] ツール詳細の共通テンプレ（使いどころ中心）は適切か
- [ ] Cases 共通テンプレに過不足はないか
- [ ] URL 命名規則は SEO 的に問題ないか
- [ ] レスポンシブブレークポイントは妥当か
- [ ] アクセシビリティ要件は実装可能か

### E. コンテンツ（`04_content.md`）

- [ ] `/learn/github` の各セクションが大学1年生に伝わるか
- [ ] **「ひとことで言うと」**の表現が分かりやすいか（特に「Issue=やることメモ」「Branch=作業用の分岐」など）
- [ ] ミニ課題（自己紹介カード）が `/workflow` の8ステップと整合しているか
- [ ] ツールページの中身が「使いどころ中心」になっているか（過剰な機能紹介になっていないか）
- [ ] Cases 4 本の章立てに **論理の飛躍** はないか
- [ ] 「実体験ベース」と「調査ベース」の境目は明確か
- [ ] 引用ルールに法的問題はないか

### F. デザイン（`05_design.md`）

- [ ] カラーパレットは WCAG AA を満たすか
- [ ] バッジが色覚多様性に配慮しているか
- [ ] **「ひとことで言うと」スタイル**は本文と調和しているか
- [ ] タイポグラフィは日本語と英語の両立ができているか
- [ ] アニメーションのやりすぎになっていないか
- [ ] モバイルレイアウトの考慮は十分か

### G. 技術スタック（`06_tech-stack.md`）

- [ ] Next.js 16 + Tailwind v4 で本当に 1〜2 週間で完走できるか
- [ ] shadcn/ui を入れない判断は妥当か
- [ ] MDX は `@next/mdx` で十分か
- [ ] Pagefind / RSS / ダーク等を Phase 2 に回す判断は妥当か
- [ ] CI 構成は最小限で十分か

### H. 全体・横断

- [ ] 駆け出しが本当に **「真似できる」** 設計か
- [ ] 著者の **実体験ベース** 方針が全体で一貫しているか
- [ ] **スコープが膨張していないか**（Phase 2 に回せるものはないか）
- [ ] **Cases が `/behind-the-scenes` の代替になっているか**（教材性が落ちていないか）
- [ ] 公開後に **継続的な更新** がしやすい構造か
